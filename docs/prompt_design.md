# AI 뉴스 스크래핑 프롬프트 설계

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| **목표** | AI 관련 뉴스를 자동으로 수집·정리하여 요약본을 생성 |
| **사용 기술** | `[채워넣기: Python, Node.js 등]` |
| **스크래핑 대상** | `[채워넣기: 대상 사이트 목록]` |
| **수집 주기** | `[채워넣기: 일간/주간/실시간]` |
| **최종 산출물** | `[채워넣기: 정리된 요약 리포트, DB 저장, 슬랙 알림 등]` |

## 2. 프롬프트 구성 (5대 요소 기반)

### 2.1 역할 (Role)

```
너는 AI/테크 뉴스 전문 데이터 엔지니어야.
웹 스크래핑, 데이터 정제, 뉴스 요약에 능숙하며
최신 AI 트렌드를 파악하고 있다.
```

### 2.2 맥락 (Context)

```
- 목적: [채워넣기: 개인 학습용 / 팀 뉴스레터 / 리서치 자동화 등]
- 환경: [채워넣기: OS, Python 버전, 사용 가능한 라이브러리 등]
- 제약사항:
  - [채워넣기: robots.txt 준수 여부]
  - [채워넣기: API 키 보유 여부 (NewsAPI, OpenAI 등)]
  - [채워넣기: 요청 빈도 제한, 비용 예산 등]
- 대상 사이트:
  - [채워넣기: 예) TechCrunch, The Verge, AI News 등]
  - [채워넣기: 각 사이트의 특성 — RSS 제공 여부, 로그인 필요 여부 등]
```

### 2.3 지시 (Instruction)

```
다음 단계를 수행해줘:

1단계: 스크래핑 구조 설계
  - 대상 사이트별 수집 전략 (RSS / HTML 파싱 / API)
  - 필요한 라이브러리와 설치 명령어
  - 프로젝트 디렉토리 구조

2단계: 스크래핑 코드 작성
  - 각 사이트별 수집 함수 구현
  - 에러 처리 (타임아웃, 차단, 구조 변경 등)
  - 중복 기사 필터링 로직

3단계: 데이터 정제 및 저장
  - 수집 데이터 정규화 (제목, URL, 날짜, 본문, 출처)
  - 저장 형식: [채워넣기: JSON / CSV / DB 등]

4단계: AI 요약 생성
  - 수집된 기사를 LLM으로 요약
  - 카테고리 자동 분류 (예: LLM, 컴퓨터비전, 로보틱스, 정책/규제 등)
  - 중요도 점수 부여 기준

5단계: 리포트 출력
  - [채워넣기: 마크다운 파일 / 이메일 / 슬랙 웹훅 / 노션 등]
```

### 2.4 데이터 (Input Data)

```
아래는 스크래핑 대상 사이트 정보다:

| 사이트 | URL | 수집 방식 | 비고 |
|--------|-----|-----------|------|
| [채워넣기] | [채워넣기] | RSS / API / HTML | [채워넣기] |
| [채워넣기] | [채워넣기] | RSS / API / HTML | [채워넣기] |
| [채워넣기] | [채워넣기] | RSS / API / HTML | [채워넣기] |

기존 코드 (있다면):
[채워넣기: 기존에 작성한 코드 또는 "없음"]

사용 가능한 API 키:
- NewsAPI: [있음/없음]
- OpenAI API: [있음/없음]
- 기타: [채워넣기]
```

### 2.5 출력 형식 (Output Format)

```
다음 형식으로 결과를 제공해줘:

1. 프로젝트 구조 (트리 형태)
2. 각 파일의 전체 코드 (복사해서 바로 실행 가능하게)
3. 실행 방법 (step-by-step 명령어)
4. 요약 리포트 예시 출력

요약 리포트 형식:
---
📅 날짜: YYYY-MM-DD
📊 수집 기사 수: N건

## 🔥 주요 뉴스 (상위 5건)
1. [제목](URL) — 한줄요약 | 출처 | 카테고리
2. ...

## 📂 카테고리별 정리
### LLM/생성형 AI
- [제목](URL) — 한줄요약
### 컴퓨터비전
- ...
### 정책/규제
- ...

## 📈 트렌드 키워드
키워드1, 키워드2, 키워드3 ...
---
```

## 3. 단계별 프롬프트 예시

### 3.1 1단계 — 구조 설계 프롬프트

```
[역할]
너는 웹 스크래핑과 데이터 파이프라인에 능숙한 시니어 파이썬 개발자야.

[맥락]
AI 관련 뉴스를 매일 자동으로 수집해서 요약 리포트를 만들려고 한다.
- Python 3.11, Windows 11 환경
- 대상 사이트: [채워넣기]
- 예산: 무료 또는 월 $20 이내

[지시]
위 요구사항에 맞는 프로젝트 구조를 설계해줘.
- 어떤 라이브러리를 사용할지 (선택 이유 포함)
- 사이트별 최적 수집 방식 (RSS vs 크롤링 vs API)
- 디렉토리 구조
- 스케줄링 방안

[출력 형식]
마크다운 테이블 + 디렉토리 트리 형태로 정리
```

### 3.2 2단계 — 코드 구현 프롬프트

```
[역할]
너는 웹 스크래핑 전문 파이썬 개발자야.

[맥락]
1단계에서 설계한 구조를 바탕으로 실제 코드를 작성한다.
- 프로젝트 구조: [1단계 결과 붙여넣기]
- 사용 라이브러리: [1단계에서 선택한 것]

[데이터]
대상 사이트 HTML 구조 예시:
[채워넣기: 크롬 개발자도구에서 복사한 HTML 일부]

[지시]
- 각 사이트별 스크래핑 함수를 작성해줘
- User-Agent 설정, 요청 간격(2~5초), 타임아웃 처리 포함
- 수집 데이터 스키마: {title, url, date, source, summary_raw}
- 테스트 코드도 함께 작성

[출력 형식]
파일별로 분리해서 전체 코드 제공. 주석은 핵심 로직에만.
```

### 3.3 3단계 — AI 요약 프롬프트

```
[역할]
너는 AI 뉴스 분석 전문가야.

[맥락]
스크래핑으로 수집된 AI 뉴스 기사들을 분석·요약한다.
- 대상 독자: [채워넣기: 개발자 / 경영진 / 일반 등]
- 요약 목적: [채워넣기: 기술 동향 파악 / 투자 판단 / 학습 등]

[데이터]
아래는 오늘 수집된 기사 목록이다:
{수집된 기사 JSON 데이터}

[지시]
1. 각 기사를 1~2줄로 요약
2. 카테고리 분류 (LLM, CV, 로보틱스, 정책, 기타)
3. 중요도 1~5 점수 부여 (기준: 산업 영향력, 기술 혁신성, 화제성)
4. 상위 5건 선정 및 심층 요약 (3~4줄)
5. 이번 주 트렌드 키워드 5개 추출

[출력 형식]
위 2.5절의 리포트 형식에 맞춰 마크다운으로 출력
```

## 4. 반복 개선 가이드

프롬프트는 한 번에 완성되지 않는다. 아래 사이클로 개선한다.

```
┌──────────────────────────────────────────────┐
│  1회차: 구조 설계 프롬프트 → 결과 확인       │
│    ↓                                         │
│  피드백: "RSS 없는 사이트 대안 추가해줘"      │
│    ↓                                         │
│  2회차: 코드 구현 → 실행 → 에러 확인         │
│    ↓                                         │
│  피드백: "이 사이트는 JS 렌더링이라 안 됨"    │
│    ↓                                         │
│  3회차: Selenium/Playwright 적용 요청        │
│    ↓                                         │
│  피드백: "요약이 너무 길어, 1줄로 줄여줘"     │
│    ↓                                         │
│  ... (목표 품질 달성까지 반복)                │
└──────────────────────────────────────────────┘
```

### 피드백 프롬프트 템플릿

```
이전 결과에서 아래를 수정해줘:

[문제점]
- [채워넣기: 구체적으로 무엇이 잘못되었는지]

[원하는 변경]
- [채워넣기: 어떻게 바뀌어야 하는지]

[유지할 부분]
- [채워넣기: 잘 되고 있어서 바꾸지 말아야 할 것]

나머지 코드/구조는 그대로 유지하고, 변경된 부분만 출력해줘.
```

## 5. 주의사항 체크리스트

```
☐ 법적 준수
  - robots.txt 확인했는가?
  - 사이트 이용약관에서 스크래핑 허용 여부 확인했는가?
  - 개인정보가 포함될 가능성은 없는가?

☐ 기술적 안전
  - 요청 간격(rate limiting)을 설정했는가? (최소 2초 권장)
  - User-Agent를 적절히 설정했는가?
  - IP 차단 대비 재시도 로직이 있는가?
  - 사이트 구조 변경 시 알림/폴백이 있는가?

☐ 데이터 품질
  - 중복 기사 필터링 로직이 있는가?
  - 날짜 파싱이 정확한가? (타임존 고려)
  - 빈 값 / 잘못된 인코딩 처리가 되는가?

☐ API 비용 관리
  - LLM 요약 시 토큰 사용량을 추정했는가?
  - 일일 비용 상한선을 설정했는가?
  - 불필요한 API 호출을 줄이는 캐싱이 있는가?
```
